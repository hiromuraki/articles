# 长文档排版自测

这是一份**样本**，不是教程。它故意做长，好让右侧目录比视口还高；故意混排二级和三级标题，好让高亮频繁换位；故意塞进短节、长节、代码、表格和公式，好让文档的高度分布不均匀。

::: {.callout-important}
读的时候顺手看三件事：**目录滚动时高亮跟不跟得上**、**目录自己会不会滚动**、**点目录跳过去后落点对不对**。
:::

## 一、这篇文档想测什么

### 1.1 三个待观察的现象

第一是**目录溢出**。十二个二级标题加三十七个三级标题，一共四十九项，远超一屏。目录本身如果不会滚，高亮跑出视野就白做了。

第二是**密集小节**。第八节里有六节各只有一句话，它们高度只有几十像素，一屏能塞下四五个。这时候高亮会快速连跳，最容易看出判定线的位置对不对。

第三是**落点漂移**。点目录项时，外层要把它滚到顶栏下方；差个几十像素，用户看到的就是"标题贴着顶栏"或"标题被顶栏吃掉"。

### 1.2 怎么用这篇文档

从上往下匀速滚一遍，眼睛盯着右侧边栏；再用 `j` / `k` 键逐篇跳，或者直接点目录最下面几项，看页面能不能准确落位。最后换一下字号（顶栏的 `A`），再滚一遍——标题的坐标会整体变化，这是最容易出错的地方。

## 二、滚动与高亮

### 2.1 判定线在哪里

高亮的判据不是"标题在屏幕里"，而是"标题越过了某条线"。这条线定在顶栏下方约四分之一屏的位置：太靠上会滞后，用户已经读了两段还停在上一节；太靠下会提前，标题刚露头就抢走高亮，看起来毛躁。

如果拿不准，打开 `?debug=1`，左下角会显示 `toc.on` 和当前 `scrollTop`，数字比眼睛可靠。

### 2.2 短小节：标题挨得很近

这一节只有两句话。它的作用是让下一节的标题出现在很近的位置，制造一次快速切换。

### 2.3 长小节：高亮会停留很久

这里必须足够长，否则测不出"停留"这件事。滚动过程中，判定线会长时间停在本节内部，高亮一动不动——这是**正确**行为，不是卡住了。判断依据是：只要本节还没被下一个标题顶掉，高亮就该留在本节。

长节还暴露另一个问题：如果目录很短，用户会误以为"高亮不动了"。所以长节通常配一个可见的章节标题，让人一眼知道自己在第几节。

再补一段，让这一节确实够长。文字本身没有信息量也没关系，因为它的用途是占位——就像排版时的假文，只是这里用真实的中文句子，顺便检查中文的行高和标点挤压。中文标点、英文标点、数字混排时，如果字体回退没处理好，会出现字距忽宽忽窄。这一段里混了 `code`、**粗体**、*斜体* 和 2026 这样的数字，正好一起看。

#### 2.3.1 小节里的四级标题

四级标题**不进目录**。它出现在这里是为了验证两件事：正文里它要正常显示为更小的字号；目录里它不该冒出来。

四级标题也不该被当成锚点目标参与高亮，否则目录项数会翻倍。

### 2.4 悬停与当前

鼠标划过目录项时是浅底加两像素左边框；当前小节是三像素左边框、加粗、更深的字色。两者刻意做得不一样，因为"我正在读"和"鼠标恰好压在这里"是两件事。

## 三、目录本身

### 3.1 目录的滚动条

目录列自己的滚动条被隐藏了。理由是它窄，一条灰色竖线压在文字边上很难看；代价是用户不容易知道"下面还有"。

补偿办法是让高亮项自动进入视野——看到高亮在动，就知道目录在动。

### 3.2 高亮项自动进入视野

实现上不是 `scrollIntoView`，因为它会连带滚动整个页面。正确做法是直接调目录容器的 `scrollTop`：高亮项在可视区上方就把它顶下来，在下方就把它推上去，留一点边距。

### 3.3 三级标题的缩进

三级标题左缩进十八像素、字号小半号。缩进靠的是 padding，所以左边框（高亮指示条）会一起内移，看起来像一根贴着小节的分支线。

层级再多就不该继续缩了。四级及以下一律不进目录，因为目录的目的是导航，不是复刻文档结构。

### 3.4 很长的目录项标题会折行，看看会不会把后面的项挤下去

这是一个刻意写长的三级标题，用来观察两件事：折行后行高是否仍然紧凑；以及它的高度变化会不会影响相邻项的定位和高亮框的居中感。

折行本身没问题，但如果目录项高度不一致，自动滚动时的"留边距"就得按元素实际高度算，不能写死。

## 四、文本块与节奏

### 4.1 段落

正文宽度控制在 780 像素左右，一行大约三十五个汉字。这个宽度是折中：再宽，视线回扫距离变长；再窄，中文的标点会把行尾撑得很松散。

段落之间的间距比行距大一点，让"段"成为视觉单位。列表和代码块前后的间距再大一些，因为它们自带边界。

### 4.2 列表

无序列表适合并列项：

- 项与项之间不该有额外空行
- 嵌套一层就够了，再多会难读
- 列表项里可以有 `行内代码`

有序列表适合步骤：

1. 先写正文
2. 再补标题
3. 最后回看目录

任务列表这里也支持，但只作为静态显示，不能勾选：

- [x] 测过二级标题
- [x] 测过三级标题
- [ ] 测过四级标题不进目录

### 4.3 引用

> 引用块用左边框和浅底表示"这是别人的话"。它的行高和正文一致，但字色略淡。
>
> 多段引用时，段与段之间仍然留空行，视觉上是一整块。

### 4.4 表格

| 元素 | 高度 | 说明 |
| --- | --- | --- |
| 单行段落 | 约 26px | 行高 1.7 |
| 二级标题 | 约 60px | 含上下边距 |
| 代码块 | 随行数 | 等宽字体 |
| 表格 | 随行数 | 单元格内边距 |

表格在窄屏会横向溢出，这时候应该允许内部滚动，而不是把整个页面撑宽。这一点在移动端尤其明显。

## 五、代码与公式

### 5.1 代码块的高度

```python
def section_at(positions, line):
    """返回最后一个 y <= line 的小节。positions 已按文档顺序排好。"""
    current = None
    for item in positions:
        if item["y"] > line:
            break
        current = item
    return current
```

代码块的高度直接由行数决定，是文档里最容易造成"高度突变"的元素。如果代码块在图片或字体加载后才定型，滚动位置就会跳。

### 5.2 行内代码与键帽

行内代码用等宽字体加浅底，`like_this`。键帽是行内 HTML：按 <kbd>Ctrl</kbd> + <kbd>K</kbd> 打开命令面板，按 <kbd>Esc</kbd> 关闭。渲染管线必须放行这类行内标签，否则会显示成字面文字。

### 5.3 公式的基线

行内公式 $e^{i\pi} + 1 = 0$ 与文字同基线，不能把行高撑开。独立公式居中：

$$
\frac{\partial \mathcal{L}}{\partial \theta} = \frac{1}{N}\sum_{i=1}^{N}\nabla_\theta \ell\bigl(x_i, y_i; \theta\bigr)
$$

公式渲染成 MathML 时，浏览器的字体回退经常导致高度差几个像素。多行公式尤其明显，所以这类文档最好在正文里少放大公式。

## 七、跨度与锚点

### 7.1 从本节跳到本节

点目录里的"7.2 跳转后的落点"，应该平滑滚到下一节标题处，并且落点留出顶栏高度。如果标题贴着顶栏下沿，说明偏移量少算了。

从这里点过去，跨度很小，动画几乎看不出；要测跨度大的，去点最后一节。

### 7.2 跳转后的落点

落点是"标题顶端 + 一点留白"对齐到视口某个固定位置。留白太少会显得局促，太多会浪费首屏，通常是顶栏高度再多四十像素左右。

落点还决定高亮：跳过去之后，那一节必须立刻成为当前小节，不能因为判定线还没越过它而停在上一节。

## 九、结构与层级

### 9.1 二级下的三级

三级标题嵌在二级的 section 里，所以文档结构其实是一棵树，不是平铺的列表。目录把它拍平，但保留层级缩进——这个取舍在笔记库里通常是对的，因为没人愿意点开折叠。

#### 9.1.1 更深的层级

四级标题在正文档里只是更小的字。它不进目录，也不参与高亮判定，这样目录项数和正文小节数不必一一对应。

### 9.2 回到三级

层级跳回三级，验证缩进能正确回退，也验证目录里相邻两项的缩进差不会累积错位。

## 十、长度与性能

### 10.1 首屏

首屏要能在一瞬间立住：标题、日期、标签、第一段。任何延迟都会让人以为页面在加载。

正文渲染在后端，首屏其实是一次完整的 HTML 请求，所以它比单页应用更快——没有客户端水合。

### 10.2 中段

中段最容易出问题。滚到这里时，目录已经滚过一段，高亮频繁换位，而用户往往在快速滑动。任何一次布局抖动都会让人注意到"目录在闪"。

减少抖动的办法是别在滚动时改 DOM 结构：只改 class，不动节点。改字号要重算坐标，但也不该重建目录节点。

### 10.3 尾部

尾部有两类问题：最后一节的标题永远等不到判定线（下面没内容了）；以及滚动到底时浏览器会把最后一点距离回弹掉。

前者的处理是到底时强制锁定最后一节，后者不影响逻辑，但会让"到底"的判断条件要留几像素余量。

## 十一、边界情况

### 11.1 标题里带 `代码`、**粗体**、$公式$

目录里只显示纯文本，所以这一节会显示成"标题里带 代码、粗体、公式"。这是有意的取舍：目录是导航，不是排版复刻。

如果目录要保留格式，就得在模板里把标题的 HTML 片段带出来，代价是注入风险，不划算。

### 11.2 标题里带 [链接](https://example.com)

带链接的标题，目录里取的是链接文字。同样只保留文字，不保留链接行为——在目录里再点一次链接没有意义。

### 11.3 这是一个刻意写得非常长的三级标题，目的就是看折行之后目录项的高度会不会把后面几项挤得难以辨认

折行之后，项与项之间要保持可区分的间距，否则读起来像一大段文字。缩进加上折行，左边距会显得很窄，所以内边距要给够。
